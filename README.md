# HH Assistant

Локальное приложение для Windows: поиск вакансий, оценка по личному профилю
через LM Studio и подготовка PDF-черновика резюме под вакансию.
Интерфейс — tkinter, данные хранятся на вашем компьютере.

## Установка

Нужны Python 3.10+ с tkinter и LM Studio с запущенным локальным сервером.
Для PDF используются Arial или Calibri из Windows Fonts.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

При первом запуске создаётся `profile.txt`. Заполните его или используйте
`examples/profile.example.txt` как основу. Раздел «Модель» задаёт адрес
сервера (по умолчанию `http://localhost:1234/v1`) и модель.
Кнопка «Проверить связь» проверяет доступность сервера.

Для запуска двойным щелчком используйте `start.cmd`: он выбирает Python
из `.venv`, если окружение создано. При прямом запуске `main.py` Windows
может выбрать другой Python, в котором зависимости ещё не установлены.

Профиль передаётся на настроенный адрес модели. При выборе удалённого сервера
данные будут отправляться ему; локальность зависит от настройки адреса.

## Поиск

В боковой панели пять разделов: «Обзор», «Поиск и фильтры», «Источники»,
«Модель» и «Журнал». Обзор показывает только вакансии текущего поиска,
поиск по должности/компании и карточку выбранной вакансии с объяснением оценки.
При открытии приложения список пуст. После успешной проверки настроек кнопка
«Начать поиск» очищает список и фильтры предыдущего запуска; история на диске
сохраняется и доступна по кнопке «История». Новые результаты появляются по мере проверки.

Оценка проходит в два этапа. Модель извлекает факты и номера строк описания
по JSON-схеме; приложение само получает дословные цитаты, проверяет их и применяет
правила. Тег опыта HH не заменяет требование стажа в описании. Наставничество
не означает допуска без опыта; диапазон зарплаты рассматривается целиком.
Неизвестные важные условия и неподтверждённые выводы попадают в отдельный фильтр
«Нужно уточнить» (`REVIEW`), файл `results/review.md` и историю. Они не входят
в счётчик подходящих, `top.md` или массовое открытие. Открыть отдельную такую
вакансию можно из карточки. `WEAK` теперь означает запасное направление.

До обращения к модели полное описание сохраняется локально в `cache/descriptions`;
после успешной оценки добавляются извлечённые факты, проверенные цитаты и решение.
Если запрос не завершился, исходник остаётся для разбора. Эти файлы не публикуются.
Правила решения соответствуют текущему личному профилю (включая минимум 40 000 ₽
на руки в месяц); изменение карьерных ограничений требует согласования правил
в `evidence_eval.py`, а не только редактирования свободного текста профиля.
JSON-схема и сверка цитат не гарантируют безошибочного толкования текста моделью.

Когда поиск полностью остановлен, кнопка «Открыть все вакансии» открывает
подходящие результаты этого запуска (`STRONG_MATCH`, `MATCH`, `WEAK`) в браузере
по умолчанию: первую ссылку сразу, следующие — каждые 20 секунд. Повторы ссылок,
отказы и ошибки оценки исключаются. Очередь включает весь текущий прогон,
независимо от текстового фильтра в таблице; история прошлых запусков не открывается.
После каждых 50 вакансий очередь ждёт нажатия «Продолжить». Перед продолжением
закройте просмотренные вкладки, чтобы освободить память браузера. Последняя пачка
может быть меньше 50. «Приостановить открытие» сохраняет позицию; продолжение
не открывает уже просмотренную часть очереди повторно. Ссылки HH с одним ID,
разными региональными поддоменами и метками перехода объединяются; объявления
с разными ID остаются отдельными. Новый поиск и закрытие приложения отменяют
очередь, не закрывая уже открытые вкладки. Позиция не сохраняется после перезапуска.
Счётчики относятся только к текущему запуску. В узком окне компания показывается
в карточке вместо отдельной колонки. Настройки прокручиваются; cookies скрыты
до нажатия «Показать / изменить cookies».

1. Настройте категории HH и/или текстовые запросы.
2. Укажите профиль и обязательные ограничения.
3. Выберите источники и нажмите «Старт».

Обычный поиск HH читает публичные страницы. Рекомендации под резюме требуют
ссылку на резюме и cookies авторизованного аккаунта. Приложение читает данные,
но не отправляет отклики и сообщения.

**Режим «только рекомендации под резюме» отключает категории, текстовые запросы,
Хабр, SuperJob и Telegram**, независимо от их отдельных переключателей.
Поиск повторяется кругами с паузой 5 минут до нажатия «Стоп».

Дополнительные источники:

- Хабр Карьера — поиск по текстовым запросам;
- SuperJob — только первая страница каждого запроса; с cookies также блок
  рекомендаций на главной. Поле ссылки на резюме пока не влияет на запросы;
- Telegram — публичные веб-превью выбранных каналов.

Сайты могут менять разметку или ограничивать запросы. Паузы снижают нагрузку,
но не гарантируют отсутствие капчи. Проверяйте журнал при пропаже результатов.

## Оценка и результаты

Сначала применяются фильтры названия, компании и тега опыта. Затем опционально
выполняется отсев заголовков моделью. При ошибке этого этапа вся пачка идёт дальше.
Полная оценка получает всё извлечённое описание, без обрезания до 4000 символов.
При отсутствии описания вакансия попадает на ручную/повторную проверку.

Вердикты: `STRONG_MATCH`, `MATCH`, `WEAK`, `REJECT`. Балл 0–100 нужен для
сортировки, числового порога нет. Всё кроме `REJECT` показывается как подходящее,
включая неопределённые случаи `WEAK`.

В `vacancy_rules.py` сохранены дополнительные ограничения для начального
уровня: тестирование, руководящие должности, явные требования опыта и вахта.
Они могут переопределить решение модели. Для другого карьерного профиля эти
правила нужно пересмотреть вместе с фильтрами в настройках. Сам по себе график
2/2 не считается ночным, отрицание вахты не считается требованием вахты.

В папке `results/`:

- `top.md` — последние подходящие оценки по текущей версии правил и моделей;
  обновляется после успешной оценки, если прошло 30 секунд, и при завершении;
- `suitable.md`, `rejected.md`, `results.csv` — накопленная история оценок;
- `skipped.md` — причины раннего отсева;
- `failed.md` — ошибки оценки и отсутствующие описания для ручного просмотра;
- `log.txt` — журнал поиска.

Окно истории показывает накопленные оценки, в том числе по прежним правилам.
Актуальная выборка находится в `top.md`. Автоматическая проверка того, что
вакансия ещё открыта, пока не выполняется.

## Кэш и повторная проверка

`cache/evaluations.sqlite3` хранит отдельные состояния: оценено, отсеяно,
ошибка, неполное описание. Ошибки и неполные описания повторяются при следующем
запуске поиска, но не на каждом круге одной сессии.

Отпечаток включает профиль, фильтры, промпты и выбранные модели. Изменение
этих параметров разрешает повторную оценку, когда вакансия снова встретится
в выдаче. Старые результаты сохраняются в истории.

После обновления старый `seen_ids.json` не используется: в нём нет причин
отсева и версии правил. Файл сохраняется, но первый новый прогон повторно
проверит встреченные вакансии. Это намеренно устраняет прежние ложные отказы.
Сам по себе кэш не загружает старые вакансии, исчезнувшие из поисковой выдачи.

Настройки и сводка записываются через временный файл с атомарной заменой;
состояния вакансий — транзакциями SQLite. Повреждённый `config.json`
показывает ошибку, а не молча заменяется настройками по умолчанию.
Запускайте один экземпляр поиска в одной папке проекта.

## Cookies и личные данные

Cookies сохраняются через `keyring` в системном хранилище учётных данных.
Длинные cookies разбиваются на небольшие части для Windows Credential Manager.
Существующие cookies из `config.json` переносятся при следующем успешном
сохранении настроек. Если хранилище недоступно, исходный файл не перезаписывается.
После переноса проекта в другую папку cookies потребуется ввести заново.

Если пакет `keyring` отсутствует или хранилище недоступно, приложение всё равно
открывается и показывает причину в журнале. Обычный поиск доступен без cookies;
рекомендации требуют восстановления доступа или повторного ввода cookies.
Сохранение остальных настроек не удаляет cookies, которые не удалось прочитать.

В репозитории используются явные исключения: личные настройки, профили,
фотография, резюме, логи, кэш, архивы и окружение Python не публикуются.
Папка `examples/` содержит только обезличенные образцы.

## Резюме под вакансию

Скопируйте `examples/resume_data.example.json` в `resume_data.json`, заполните
реальными фактами и запустите:

```powershell
.\.venv\Scripts\python.exe resume_tailor.py
```

Вставьте описание вакансии. Навыки и учебные курсы выбираются только из
исходных списков; число пунктов опыта не увеличивается. Результат —
PDF-черновик и соседний файл `_review.json` с исходными данными и адаптированной
версией. Проверьте переформулированные обязанности, достижения и «Обо мне»:
семантическую достоверность свободного текста программа гарантировать не может.
Фотография `photo.jpg`/`photo.png` необязательна.

## Проверки и структура

### Два этапа поиска

Сначала приложение собирает выбранные страницы и проверяет названия пачками.
Затем читает описания оставшихся вакансий. Поэтому первые полные оценки
появятся после завершения сбора. Остановка во время сбора не отмечает очередь
как просмотренную: следующий запуск сможет обработать её заново.

В настройках доступны отдельные модели для отсева и оценки. Быстрая модель
получает только названия. Координация, проекты, поддержка, администрирование,
ассистентские и другие близкие роли защищены от её исключений. Пользовательские
стоп-слова и фильтр опыта остаются отдельными настройками до нейросетевого отсева.
Исключение моделью применяется только к ограниченному списку явно чужих
профессий; неоднозначные названия проходят полную проверку.

Неизвестные зарплата и оформление по ТК не означают отказ: они отображаются
в причине как вопросы работодателю. Подтверждённое несоответствие по опыту,
оформлению или другим ограничениям по-прежнему исключает вакансию. Ошибки
извлечения и неоднозначное содержание роли остаются в «Нужно уточнить».

Для автоматического освобождения памяти между этапами можно установить
`manage_local_models: true` в локальном `config.json`. Требуются установленный
CLI `~/.lmstudio/bin/lms`, локальный сервер LM Studio и точные `modelKey` в
`lm_model` / `lm_model_fast`. Приложение выгружает только модели настроенной
пары; если загружена посторонняя модель или выполняется другой запрос,
показывает ошибку. Контекст по умолчанию — 8192, параллельных запросов — один.
Необязательный словарь `model_gpu` задаёт долю GPU для каждой модели.
`model_context` задаёт размер окна; при несовпадении модель перезагружается.
`lm_reasoning_effort` управляет reasoning основной модели (`none` по умолчанию).
Быстрый отсев остаётся без reasoning при использовании отдельной модели.
Поддержка режима зависит от модели; Qwen3-30B-A3B-Instruct-2507 работает только
без thinking. Режим и контекст входят в версию кэша. В аудите сохраняются
доступная статистика токенов и объём reasoning, отдельно от финального ответа.
Большие модели используют также оперативную память. Во время загрузки модели
остановка может ожидать завершения команды загрузки (до четырёх минут).

Кэш решений зависит от версии правил и моделей; изменение версии запускает
переоценку, сохраняя старую историю.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют синтетические данные и заглушки сети; не обращаются к HH,
LM Studio и личным cookies.

- `main.py` — интерфейс поиска, источники и рабочий цикл;
- `desktop_ui.py` — оформление, навигация, настройки и список вакансий;
- `vacancy_rules.py` — извлечение описаний и фильтры;
- `llm_client.py` — общий потоковый клиент LM Studio;
- `storage.py` — версии оценок и надёжная запись файлов;
- `settings.py` — настройки и системное хранилище cookies;
- `resume_tailor.py` — адаптация фактов и PDF.

Остановка ожидает завершения текущего сетевого чтения. Если модель перестала
присылать данные, таймаут может составить до 10 минут. Длинные описания также
должны помещаться в контекст выбранной модели; при ошибке вакансия остаётся
доступной для повторной проверки.

Проверка опыта учитывает раздел и весь пункт требования: желательный опыт
не равен обязательному стажу, а опыт компании не относится к кандидату.
Рабочее владение инструментами не считается экспертным уровнем; приложение
показывает необходимость сопоставить практические навыки с требованиями.
