# WORKAholic

Локальное приложение для Windows: поиск вакансий, оценка по личному профилю
через LM Studio и подготовка PDF-черновика резюме под вакансию.
Интерфейс — tkinter, данные хранятся на вашем компьютере.

## Установка

Нужны Python 3.10+ с tkinter и LM Studio с запущенным локальным сервером.
Для PDF используются Arial или Calibri из Windows Fonts.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

При первом запуске создаётся `profile.txt`. Заполните его или используйте
`examples/profile.example.txt` как основу. Раздел «Модель» задаёт адрес
сервера (по умолчанию `http://localhost:1234/v1`) и модель.
Кнопка «Проверить связь» проверяет доступность сервера.

Для запуска двойным щелчком используйте `start.cmd`: он выбирает Python
из `.venv`, если окружение создано. При прямом запуске `main.py` Windows
может выбрать другой Python, в котором зависимости ещё не установлены.

Профиль передаётся на настроенный адрес модели. При выборе удалённого сервера
данные будут отправляться ему; локальность зависит от настройки адреса.

## Поиск

В боковой панели пять разделов: «Обзор», «Поиск и фильтры», «Источники»,
«Модель» и «Журнал». Обзор показывает только вакансии текущего поиска,
поиск по должности/компании и карточку выбранной вакансии с объяснением оценки.
При открытии приложения список пуст. После успешной проверки настроек кнопка
«Начать поиск» очищает список и фильтры предыдущего запуска; история на диске
сохраняется и доступна по кнопке «История». Новые результаты появляются по мере проверки.

В строке «Продолжить очередь» две кнопки: «Только новые результаты» очищает
таблицу и показывает только новые оценки; «С прежними результатами» сохраняет
таблицу и возвращает оценки из истории, включая «Нужно уточнить», даже после
перезапуска приложения. Обе продолжают одну и ту же очередь; сохранённые оценки
на диске не удаляются.
Кнопка «Вернуть результаты» делает это без запуска поиска. Возвращаются результаты
всех запусков после последнего сброса данных; счётчики остаются за текущий запуск.
Обе кнопки продолжения проверяют только сохранённые вакансии для текущих
фильтров поиска, без нового сбора. Действует лимит полных проверок. Если очередь пуста
или изменились фильтры поиска, приложение сообщает об отсутствии очереди. Смена модели или правил оценки больше не меняет очередь.
При завершении журнал и строка состояния показывают причину остановки и остаток.
При загрузке описания обычный HTTP 403 переносит вакансию в отложенные.
Они не запрашиваются при обычном запуске и продолжении очереди, даже если
снова встретились в выдаче. Кнопка «Вернуть отложенные» в боковой панели
возвращает их в очередь текущих настроек и запускает её проверку без сбора.
Ранее записанные отказы HTTP 403 переносятся один раз при первом запуске
с обновлением. Остаток обычной очереди и количество отложенных показаны отдельно. Перед следующей вакансией выдерживается пауза 60 секунд (прерывается
кнопкой «Остановить»). Два 403 подряд или три за прогон останавливают поиск;
успешное описание сбрасывает только счётчик подряд. Капча, HTTP 429 и ограничения
при сборе выдачи останавливают поиск сразу. Очередь сохраняется; повторов
проблемной страницы внутри одного прогона нет.
Журнал различает HTTP 403 (запрет доступа), HTTP 429 (ограничение частоты)
и переход на страницу капчи. Сам по себе HTTP 403 не подтверждает капчу.
Диагностика включает коды переходов, тип страницы, размер и фиксированные
признаки ошибки. HTML, cookies, заголовки авторизации и параметры ссылок
в диагностический журнал не записываются.

Оценка проходит в два этапа. Модель извлекает факты и номера строк описания
по JSON-схеме; приложение само получает дословные цитаты, проверяет их и применяет
правила. Тег опыта HH не заменяет требование стажа в описании. Наставничество
не означает допуска без опыта; диапазон зарплаты рассматривается целиком.
Неизвестные важные условия и неподтверждённые выводы попадают в отдельный фильтр
«Нужно уточнить» (`REVIEW`), файл `results/review.md` и историю. Они не входят
в счётчик подходящих, `top.md` или массовое открытие. Открыть отдельную такую
вакансию можно из карточки. `WEAK` теперь означает запасное направление.

До обращения к модели полное описание сохраняется локально в `cache/descriptions`;
после успешной оценки добавляются извлечённые факты, проверенные цитаты и решение.
Если запрос не завершился, исходник остаётся для разбора. Эти файлы не публикуются.
Правила решения соответствуют текущему личному профилю (включая минимум 40 000 ₽
на руки в месяц); изменение карьерных ограничений требует согласования правил
в `evidence_eval.py`, а не только редактирования свободного текста профиля.
Отсутствие зарплаты не даёт автоматический отказ: вакансия может оставаться
MATCH/WEAK с вопросом об оплате. Сумма не угадывается. Для MATCH наличие
уточнений снижает балл сортировки с 80 до 65, но не исключает вакансию.
Обещания обучения в разделе «Чему научитесь» не подтверждают рабочую роль.
Для проектных и технических ролей дополнительно проверяется сочетание
обязанностей: анализ требований, моделирование процессов, создание автоматизаций,
построение инфраструктуры и преподавание. Несколько таких направлений требуют
уточнения их доли (REVIEW), а не автоматического отказа. Это ограниченная
проверка характерных формулировок, а не гарантия полного понимания роли.
Если модель пропустила зарплату, приложение ищет явно указанную оплату
в описании. Сумма до налогов не превращается автоматически в сумму на руки;
неизвестные период и условия остаются вопросами работодателю.
JSON-схема и сверка цитат не гарантируют безошибочного толкования текста моделью.

Когда поиск полностью остановлен, кнопка «Открыть список · N» открывает
вакансии, видимые в текущей таблице с учётом фильтра и текстового поиска.
Можно выбрать подходящие, REVIEW, отклонённые или все результаты текущего
прогона. Открываются также все ссылки сгруппированных вариантов; дубли ссылок
удаляются. Браузер — системный по умолчанию; отдельное окно не гарантируется.
Первая ссылка открывается сразу, следующие — каждые 20 секунд.
Список фиксируется при запуске открытия: смена фильтра не меняет текущую пачку.
Чтобы открыть другой список, нажмите «Сбросить открытие», выберите фильтр и
запустите открытие заново. Сброс не закрывает вкладки и не удаляет результаты.
После каждых 50 вакансий очередь ждёт нажатия «Продолжить». Перед продолжением
закройте просмотренные вкладки, чтобы освободить память браузера. Последняя пачка
может быть меньше 50. «Приостановить открытие» сохраняет позицию; продолжение
не открывает уже просмотренную часть очереди повторно. Ссылки HH с одним ID,
разными региональными поддоменами и метками перехода объединяются; объявления
с разными ID остаются отдельными. Новый поиск и закрытие приложения отменяют
очередь, не закрывая уже открытые вкладки. Позиция не сохраняется после перезапуска.
Счётчики относятся только к текущему запуску. В узком окне компания показывается
в карточке вместо отдельной колонки. Настройки прокручиваются; cookies скрыты
до нажатия «Показать / изменить cookies».

1. Настройте категории HH и/или текстовые запросы.
2. Укажите профиль и обязательные ограничения.
3. Выберите источники и нажмите «Старт».

Обычный поиск HH читает публичные страницы. Рекомендации под резюме требуют
ссылку на резюме и cookies авторизованного аккаунта. При загрузке описаний HH
используются сохранённые cookies, если они заданы; они отправляются только
по HTTPS на hh.ru и его поддомены. Приложение читает данные,
но не отправляет отклики и сообщения.

**Режим «только рекомендации под резюме» отключает категории, текстовые запросы,
Хабр, SuperJob и Telegram**, независимо от их отдельных переключателей.
Поиск повторяется кругами с паузой 5 минут до нажатия «Стоп».

Дополнительные источники:

- Хабр Карьера — поиск по текстовым запросам;
- SuperJob — только первая страница каждого запроса; с cookies также блок
  рекомендаций на главной. Поле ссылки на резюме пока не влияет на запросы;
- Telegram — публичные веб-превью выбранных каналов.

Сайты могут менять разметку или ограничивать запросы. Паузы снижают нагрузку,
но не гарантируют отсутствие капчи. Проверяйте журнал при пропаже результатов.

## Оценка и результаты

Сначала применяются фильтры названия, компании и тега опыта. Затем опционально
выполняется отсев заголовков моделью. При ошибке этого этапа вся пачка идёт дальше.
Полная оценка получает всё извлечённое описание, без обрезания до 4000 символов.
При отсутствии описания вакансия попадает на ручную/повторную проверку.

Вердикты: `STRONG_MATCH`, `MATCH`, `WEAK`, `REVIEW`, `REJECT`. Балл нужен для
сортировки. REVIEW означает ручную проверку и не считается подходящим;
WEAK — запасное направление.

В `vacancy_rules.py` сохранены дополнительные ограничения для начального
уровня: тестирование, руководящие должности, явные требования опыта и вахта.
Они могут переопределить решение модели. Для другого карьерного профиля эти
правила нужно пересмотреть вместе с фильтрами в настройках. Сам по себе график
2/2 не считается ночным, отрицание вахты не считается требованием вахты.

В папке `results/`:

- `top.md` — последние подходящие оценки по текущей версии правил и моделей;
  обновляется после успешной оценки, если прошло 30 секунд, и при завершении;
- `suitable.md`, `rejected.md`, `results.csv` — накопленная история оценок;
- `skipped.md` — причины раннего отсева;
- `failed.md` — ошибки оценки и отсутствующие описания для ручного просмотра;
- `log.txt` — журнал поиска.

Окно истории показывает накопленные оценки, в том числе по прежним правилам.
Актуальная выборка находится в `top.md`. Автоматическая проверка того, что
вакансия ещё открыта, пока не выполняется.

## Кэш и повторная проверка

`cache/evaluations.sqlite3` хранит отдельные состояния: оценено, отсеяно,
ошибка, неполное описание. Ошибки и неполные описания повторяются при следующем
запуске поиска, но не на каждом круге одной сессии.

Отпечаток включает профиль, фильтры, промпты и выбранные модели. Изменение
этих параметров разрешает повторную оценку, когда вакансия снова встретится
в выдаче. Старые результаты сохраняются в истории.

После обновления старый `seen_ids.json` не используется: в нём нет причин
отсева и версии правил. Файл сохраняется, но первый новый прогон повторно
проверит встреченные вакансии. Это намеренно устраняет прежние ложные отказы.
Сам по себе кэш не загружает старые вакансии, исчезнувшие из поисковой выдачи.

Настройки и сводка записываются через временный файл с атомарной заменой;
состояния вакансий — транзакциями SQLite. Повреждённый `config.json`
показывает ошибку, а не молча заменяется настройками по умолчанию.
Запускайте один экземпляр поиска в одной папке проекта.

## Cookies и личные данные

Cookies сохраняются через `keyring` в системном хранилище учётных данных.
Длинные cookies разбиваются на небольшие части для Windows Credential Manager.
Существующие cookies из `config.json` переносятся при следующем успешном
сохранении настроек. Если хранилище недоступно, исходный файл не перезаписывается.
После переноса проекта в другую папку cookies потребуется ввести заново.

Если пакет `keyring` отсутствует или хранилище недоступно, приложение всё равно
открывается и показывает причину в журнале. Обычный поиск доступен без cookies;
рекомендации требуют восстановления доступа или повторного ввода cookies.
Сохранение остальных настроек не удаляет cookies, которые не удалось прочитать.

В репозитории используются явные исключения: личные настройки, профили,
фотография, резюме, логи, кэш, архивы и окружение Python не публикуются.
Папка `examples/` содержит только обезличенные образцы.

## Резюме под вакансию

Скопируйте `examples/resume_data.example.json` в `resume_data.json`, заполните
реальными фактами и запустите:

```powershell
.\.venv\Scripts\python.exe resume_tailor.py
```

Вставьте описание вакансии. Навыки и учебные курсы выбираются только из
исходных списков; число пунктов опыта не увеличивается. Результат —
PDF-черновик и соседний файл `_review.json` с исходными данными и адаптированной
версией. Проверьте переформулированные обязанности, достижения и «Обо мне»:
семантическую достоверность свободного текста программа гарантировать не может.
Фотография `photo.jpg`/`photo.png` необязательна.

## Проверки и структура

### Два этапа поиска

Сначала приложение собирает выбранные страницы и проверяет названия пачками.
Затем читает описания оставшихся вакансий. Поэтому первые полные оценки
появятся после завершения сбора. Остановка во время сбора не отмечает очередь
как просмотренную: следующий запуск сможет обработать её заново.

В настройках доступны отдельные модели для отсева и оценки. Быстрая модель
получает только названия. Координация, проекты, поддержка, администрирование,
ассистентские и другие близкие роли защищены от её исключений. Пользовательские
стоп-слова и фильтр опыта остаются отдельными настройками до нейросетевого отсева.
Исключение моделью применяется только к ограниченному списку явно чужих
профессий; неоднозначные названия проходят полную проверку.

Неизвестные зарплата и оформление по ТК не означают отказ: они отображаются
в причине как вопросы работодателю. Подтверждённое несоответствие по опыту,
оформлению или другим ограничениям по-прежнему исключает вакансию. Ошибки
извлечения и неоднозначное содержание роли остаются в «Нужно уточнить».

Для автоматического освобождения памяти между этапами можно установить
`manage_local_models: true` в локальном `config.json`. Требуются установленный
CLI `~/.lmstudio/bin/lms`, локальный сервер LM Studio и точные `modelKey` в
`lm_model` / `lm_model_fast`. Приложение выгружает только модели настроенной
пары; если загружена посторонняя модель или выполняется другой запрос,
показывает ошибку. Контекст по умолчанию — 8192, параллельных запросов — один.
Необязательный словарь `model_gpu` задаёт долю GPU для каждой модели.
`model_context` задаёт размер окна; при несовпадении модель перезагружается.
`lm_reasoning_effort` управляет reasoning основной модели (
one` по умолчанию).
Быстрый отсев остаётся без reasoning при использовании отдельной модели.
Поддержка режима зависит от модели; Qwen3-30B-A3B-Instruct-2507 работает только
без thinking. Режим и контекст входят в версию кэша. В аудите сохраняются
доступная статистика токенов и объём reasoning, отдельно от финального ответа.
Большие модели используют также оперативную память. Во время загрузки модели
остановка может ожидать завершения команды загрузки (до четырёх минут).

Кэш решений зависит от версии правил и моделей; изменение версии запускает
переоценку, сохраняя старую историю.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют синтетические данные и заглушки сети; не обращаются к HH,
LM Studio и личным cookies.

- `main.py` — интерфейс поиска, источники и рабочий цикл;
- `desktop_ui.py` — оформление, навигация, настройки и список вакансий;
- `vacancy_rules.py` — извлечение описаний и фильтры;
- `llm_client.py` — общий потоковый клиент LM Studio;
- `storage.py` — версии оценок и надёжная запись файлов;
- `settings.py` — настройки и системное хранилище cookies;
- `resume_tailor.py` — адаптация фактов и PDF.

Остановка ожидает завершения текущего сетевого чтения. Если модель перестала
присылать данные, таймаут может составить до 10 минут. Длинные описания также
должны помещаться в контекст выбранной модели; при ошибке вакансия остаётся
доступной для повторной проверки.

Проверка опыта учитывает раздел и весь пункт требования: желательный опыт
не равен обязательному стажу, а опыт компании не относится к кандидату.
Рабочее владение инструментами не считается экспертным уровнем; приложение
показывает необходимость сопоставить практические навыки с требованиями.

Похожие объявления с одинаковыми названием, работодателем и вердиктом
группируются в текущем списке и top.md при сходстве описаний от 97%.
Это группировка для просмотра, а не перенос оценок: каждый вариант имеет
свою ссылку, а различающиеся строки описаний видны в карточке. Массовое
открытие включает все ссылки группы. CSV сохраняет отдельные объявления.


### Быстрый поиск и продолжение очереди

В «Поиск и фильтры» доступны режим «Быстрый HH» (только HH) и «Расширенный» (все включённые площадки), лимит полных проверок (0 — без лимита) и завершение после одного прохода. Режим опыта «Без опыта + 1–3 года» чередует потоки без опыта и 1–3 года для каждого источника. Между запусками сохраняется следующий источник: сбор не начинается каждый раз с первого запроса. Быстрый режим прекращает сбор после накопления примерно двух бюджетов проверки (возможен избыток последней страницы). Лимит 200 относится к полученным непустым описаниям, отправленным на оценку или пересчитанным из кэша; ошибки модели тоже расходуют этот бюджет.

Очередь сохраняется в `cache/search.sqlite3`. При неизменных фильтрах следующий запуск продолжает необработанные вакансии, даже после изменения модели или правил оценки. При смене области поиска или предварительных фильтров очередь остаётся отдельно. Новые загруженные описания кэшируются на сутки; затем запрашиваются заново. Кэш не подтверждает, что объявление ещё открыто. Старые файлы аудита автоматически в этот кэш не импортируются. В приоритете проектные роли и вакансии без опыта; каждая пятая позиция при наличии — из других ролей. В коротком режиме источники после заполнения очереди могут не попасть в текущий проход: для широкого охвата используйте расширенный режим.

Извлечённые факты кэшируются по тексту, модели, промпту/схеме, reasoning и контексту. Изменение критериев пересчитывает решение без генерации при совпадении этого ключа. Кэш заполняется новыми оценками; старые JSON-аудиты автоматически не импортируются. Неподтверждённые поля по-прежнему требуют проверки. Повтор модели возвращает только проблемные поля с сохранением полного исходного текста.

Полная оценка использует явные «Критерии полной оценки» в настройках. Текстовый профиль задаёт контекст быстрого отсева и подготовки резюме, но не заменяет эти критерии. По умолчанию сохранены согласованные стоп-факторы и минимум 40 000 ₽ на руки. Неизвестные условия не становятся автоматическим отказом.

В карточке доступны постоянные отметки просмотра/отклика и «Подготовить резюме» с переносом описания. Для группы похожих объявлений отметка относится к основной ссылке. Генерация резюме запускается пользователем после остановки поиска; отправка отклика не автоматизирована. Причины REVIEW разделены в карточке на проверку разбора и уточнение условий. Отметки переживают изменение модели и правил.

Время генерации засчитывается в интервал между запросами описаний; дополнительные паузы после десятка оценок убраны. При капче/403/429 HH поиск останавливается с сохранением очереди. Журнал содержит время сбора и загрузки/оценки, аудит — метрики всех успешных ответов модели, включая повторы. Ранний отсев по описанию работает только в режиме сравнения и не исключает вакансии до основной модели.

## Если вакансия открывается только в браузере

Сохраните открытую страницу HH через Ctrl+S в формате HTML («только HTML»).
В приложении нажмите «Загрузить HTML вакансии» внизу боковой панели, выберите
файл и нажмите «Продолжить очередь». Работает для вакансий, уже находящихся
в очереди. Номер вакансии берётся из canonical/og:url, описание — из JobPosting.
Файл без этих данных отклоняется. Новая вакансия этим действием не добавляется.
Сохраняется только описание, номер и время импорта в локальном cache/;
HTML целиком, cookies и скрипты страницы не копируются и не выполняются.
Импортированное описание используется при следующих проверках этой вакансии
без обращения к HH; его актуальность не проверяется. Для обновления импортируйте
свежую страницу. Остальные вакансии загружаются обычным способом.

Обязательный английский B2/C1/C2 и самостоятельный найм с руководством командой
при ответственности за бюджет или полный цикл продукта требуют уточнения (REVIEW).
Название Project Manager само по себе не отменяет эти требования. Проверка ограничена
явными формулировками; желательные навыки и обещания обучения не блокируют допуск.

Ошибки загрузки и оценки сохраняются также в REVIEW-истории с пометкой
«Проверка не завершена» и остаются доступными для повторной попытки.
История теперь включает REJECT с отдельным фильтром для проверки ложных отказов.
Предварительный отсев по-прежнему находится в skipped.md, а не в REVIEW.
Отрицания и добровольность ночей/поездок не подтверждают обязательный запрет;
учебный опыт без отдельного требования коммерческого стажа не означает стаж работы.
Очередь формата queue-v2 не подхватывает старые очереди автоматически; перед этим
обновлением активные очереди были очищены по запросу пользователя.

## Обычный запуск

«Начать поиск» автоматически сначала обрабатывает оставшуюся очередь для
текущих фильтров. Если очередь успешно закончилась и лимит проверок ещё
не достигнут, в том же запуске собираются новые вакансии. Лимит общий для
обоих этапов. При ошибках или ограничении HH автоматический переход не
пытается повторять проблемные вакансии. «Только сохранённая очередь» —
отдельный режим без нового сбора. После остановки можно снова использовать
основную кнопку; выбор между новым поиском и продолжением обычно не нужен.

Чтение суточного кэша описаний не ждёт сетевую паузу и не сбрасывает счётчик
HTTP 403. Сброс возможен после успешного сетевого получения непустого описания
HH, а не после чтения кэша или импортированного HTML. Если источник не удалось
собрать, итог отдельно сообщает о неполном сборе; в журнале есть источник и страница.

## Темп запросов HH

Начальные паузы — 20–30 секунд. Поиск и загрузка описаний используют общий
контроль интервала между запросами HH, включая переходы после сетевых ошибок.
Время генерации модели засчитывается в ожидание. Чтение локального кэша не
вызывает этот сетевой ограничитель. Ожидание прерывается кнопкой остановки.
HTTP 429 и капча останавливают прогон с сохранением очереди, без автоматического
повторения запроса. Эти паузы снижают нагрузку, но не гарантируют отсутствие
ограничений со стороны HH; значение можно изменить в настройках поиска.


## Приоритет начального уровня

При режиме «Без опыта + 1–3 года» сначала собираются все выбранные источники HH
без опыта, затем поток 1–3 года. Полная проверка (включая сохранённую очередь)
идёт в порядке: стажировки/без опыта, junior с неуказанным опытом, другие объявления
без тега опыта, 1–3 года. Внутри группы техническая поддержка и сопровождение
идут первыми. Это приоритет обработки известных вакансий, а не гарантия полного
охвата площадки: остаются ограничения страниц и объёма сбора.

Порядок не меняет жёсткие требования: обязательный профильный опыт, ночи,
отсутствие ТК и зарплата ниже установленного минимума по-прежнему проверяются.
Основные направления оценки задаются списком `decision_policy.preferred_roles`;
остальные допустимые направления остаются запасными. Форма настроек сохраняет
этот список при запуске. Свободный текст профиля не заменяет правила оценки.

Локальные запросы LM Studio к localhost/127.0.0.1/::1 идут напрямую, независимо
от системного HTTP-прокси. Прокси внешних источников не изменяется.

Для ограниченного запуска можно выбрать «Быстрый HH», 200 полных проверок,
3 страницы на источник и один проход. Оставшаяся очередь сохраняется;
следующий обычный запуск сначала продолжит её. Лимит 0 означает без ограничения
полных проверок. Капча и ограничения сайта всё ещё могут остановить работу.
