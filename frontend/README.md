# WORKAholic — веб-интерфейс

Откройте `index.html` в браузере. `main.py` по-прежнему запускает отдельный
рабочий интерфейс tkinter: подключения веб-части к поиску ещё нет.

## Что работает в демо

Шесть маршрутов: помощник, вакансии, отклики, профиль, избранное и история.
Общие данные обеспечивают согласованность статусов, избранного и критериев.
Фильтры работают совместно с поиском. На мобильном есть отдельное меню и возврат
из деталей с сохранением позиции списка. Критерии редактируются в диалоге:
сохранение, отмена, проверка длины и отдельное подтверждение предложения помощника.

Данные вымышленные, взяты из прежнего макета. Изменения живут только в памяти
страницы и сбрасываются при обновлении. Реальные результаты, cookies, профиль,
SQLite и LM Studio не читаются и не изменяются. Изменение критериев не вызывает
переоценку примеров. Нет автоматических откликов или имитации ответов AI.

Поиск, история и диалог помощника не подключены. Ссылка на оригинал появляется
только при корректном HTTP(S) URL. Без ссылки показывается пояснение. Внизу страницы
вакансий есть отдельные «Демо-сценарии»: состояния и просмотр механики пачек.

## Устройство

Стек сохранён: HTML, CSS и обычный JavaScript, без новых библиотек и сборки.

- `app.js`: исходные примеры, базовое состояние и уведомления.
- `ui-state.js`: общие критерии, изменения статусов и избранного, безопасные ссылки.
- `vacancy-view.js`: общий список и детали для вакансий и избранного.
- `career.js`: шесть hash-маршрутов, профиль, помощник, отклики и мобильное меню.
- `workspace.css`: общие токены, типографика, композиция всех страниц.
- Прежние стили сохраняются; уточнения подключены после них.

Ключи статусов прежние: `Не просмотрено`, `Интересно`, `Откликнулся`, `Не подходит`.
Пользователь видит соответственно «Не просмотрена», «Планирую откликнуться»,
«Откликнулся», «Не интересует». Это независимая от оценки соответствия сущность.

## Проверка

Синтаксис: `node --check app.js`, затем аналогично `ui-state.js`, `vacancy-view.js`,
`career.js`. TypeScript, сборщик и линтер в проекте не настроены.

Браузер: `node check-ui.cjs`, `node check-final-ui.cjs` и `node check-contrast.cjs` из этой папки.
Требуются уже установленные Playwright и Edge; если пакет находится вне проекта,
задайте путь к его каталогу node_modules через `NODE_PATH`. Тесты ничего не устанавливают.

Браузерные сценарии проверяют 12 пунктов задания, все шесть страниц на ширинах
360, 390, 768, 1024, 1440, 1920 px, модальные окна, клавиатуру, состояния данных,
копирование, отмену удаления из избранного и сброс после перезагрузки.
Скриншоты всех страниц: `screenshots/<route>-1440.png` и `<route>-390.png`.

Контраст измеряется по вычисленным браузером цветам видимого текста и фона.
Результаты записываются в `contrast-report.json`. Это проверка текста, не полный
аудит WCAG: скринридер и все комбинации системных тем отдельно не проверялись.

Следующий отдельный этап — согласовать подключение локального поиска, истории,
хранения действий и настоящего анализа. Серверные изменения в эту итерацию не входят.

## Завершающая UX-итерация

Выбор вакансии восстанавливается отдельно для списка и избранного на desktop;
на мобильном раздел открывается списком. Ошибка и загрузка общие для помощника
и вакансий. Изменённые критерии сравниваются с условиями исходной демо-подборки:
до пересчёта показано предупреждение, а отмена и сохранение без изменений его
не вызывают. Ctrl+F остаётся браузерным. Иконки — локальные SVG без зависимостей.

Обновление 12.10.2026: предупреждение об устаревших оценках общее для всех разделов;
при возврате исходных критериев оно исчезает. На мобильном критерии сворачиваются,
фильтры малого избранного раскрываются кнопкой, заполненные отклики идут первыми
при входе. Меню удерживает фокус и блокирует фоновую прокрутку. Длинный разбор
прокручивается вместе со страницей. Скриншоты: `screenshots/review.html`.
