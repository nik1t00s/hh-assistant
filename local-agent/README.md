# Запасной локальный агент

Подготовлено 4 октября 2026. Ничего не установлено и не скачано.

Схема: локальная модель → сервер LM Studio → DeepSeek Harness → файлы и инструменты.
Модель генерирует ответы и запросы инструментов; Harness ведёт диалог и выполняет
разрешённые операции. Обучать свою модель с нуля для этого не требуется.
Этот комплект готовит подключение, но сам не является агентом.

## Что уже есть на этом компьютере

RTX 2070 SUPER: 8192 MiB VRAM; RAM: 31,9 GiB; Node.js: v24.18.0.
LM Studio и его CLI установлены. Список моделей проверен через `lms ls --json`.

| Уже скачанная модель | Размер файла | Как я предлагаю использовать |
| --- | --- | --- |
| qwen/qwen3-8b, Q4_K_M | около 5,0 ГБ | Первый кандидат для проверки инструментов |
| qwen/qwen3.5-9b, Q4_K_M | около 6,5 ГБ | Альтернатива после проверки расхода памяти |
| qwen3-coder-30b-a3b-instruct, Q4_K_M | около 18,6 ГБ | Позже сравнить качество и скорость с выгрузкой части слоёв в RAM |

Это стартовые предположения по имеющимся файлам и памяти, а не измеренный рейтинг.
Размер файла не учитывает память контекста и служебные буферы. Даже MoE-модели
нужно разместить целиком в доступной памяти. Начни с контекста 8192 и одной задачи.
Не запускай несколько агентов параллельно на этой видеокарте.

В момент подготовки Gemma 4 26B была занята генерацией. Модели не переключались.
Закончи поиск в HH Assistant перед выделением LM Studio локальному агенту:
приложение умеет самостоятельно переключать свои модели.

## Проверка после возвращения домой

1. В LM Studio вручную загрузи Qwen3 8B, начни с контекста 8192.
2. В Developer включи локальный сервер на порту 1234. Используй loopback,
   отключи доступ из локальной сети. Если включена авторизация, передай ключ
   через переменную `LOCAL_LLM_API_KEY`; не записывай настоящий ключ в шаблон.
3. Выполни из корня проекта:

```powershell
Copy-Item .\local-agent\config.example.json .\local-agent\config.local.json
python .\local-agent\check.py
```

Скопируй точный ID из выведенного списка в поле `model` файла config.local.json.
Список `/models` может включать незагруженные модели: он проверяет только сервер.
Затем, когда LM Studio свободен:

```powershell
python .\local-agent\check.py --smoke
python .\local-agent\check.py --tools
```

Второй тест проверяет структурированный вызов инструмента и передачу результата
обратно модели. Он не выполняет команды и не читает файлы проекта. Если не проходит,
проверь шаблон чата и поддержку tools в установленной версии LM Studio.
Если закончился бюджет ответа из-за рассуждений, увеличь max_tokens или настрой
режим рассуждений самой модели. Успех этого теста ещё не доказывает качество
редактирования кода и совместимость всех инструментов Harness.

Скрипт работает на стандартной библиотеке Python. По умолчанию он только получает
список моделей; `--offline` проверяет JSON вообще без сети. Он не устанавливает
пакеты, не загружает и не выгружает модели. HTTP-переадресации и прокси отключены.

## Когда самостоятельно установишь Harness

Официальный репозиторий: https://github.com/deepseek-ai/deepseek-harness
Запуск npm-версии из официального README: `npx @deepseek-ai/dsh web`.
**Эта команда может скачивать пакет; сейчас она не выполнялась.**
Запускай из папки нужного проекта. В интерфейсе выбери workspace проекта.

В Settings → Models добавь Custom model API:

| Поле | Значение |
| --- | --- |
| Provider ID | local-lmstudio |
| Base URL | http://127.0.0.1:1234/v1 |
| API protocol | OpenAI Chat Completions |
| Credential | При отключённой авторизации — локальная заглушка lm-studio, если поле обязательно; иначе настоящий локальный ключ |
| Model ID | Точный ID из check.py |
| Context window | 8192, совпадает с загрузкой в LM Studio |
| Max output tokens | Для начала 2048; бюджет подбирается под модель |
| Input types | Text для первых задач |

Сохрани провайдер, выбери его модель и создай новую сессию.
При ошибках ролей/лимита ответа у провайдера предусмотрены compat-настройки
`supportsDeveloperRole: false` и `maxTokensField: max_tokens`.
Точное размещение смотри в официальной инструкции:
https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md
Harness находится в developer preview: после установки сверь поля с его версией.
Здесь намеренно нет файла, который перезаписывает глобальные настройки Harness.

## Первая рабочая задача

В корне проекта подготовлен AGENTS.md с картой исходников и правилами.
Если установленная версия Harness его не подхватила, явно попроси прочитать файл.
Правила в тексте не заменяют ограничения исполнения и подтверждения в Harness.
Проверь активную политику доступа перед разрешением команд.

Первая задача для вставки в диалог:

> Прочитай AGENTS.md и README.md. Кратко объясни связь desktop_ui.py,
> main.py и llm_client.py. Ничего не меняй и не запускай поиск вакансий.
> Укажи конкретные функции, на которых основано объяснение.

Затем дай одну небольшую правку с проверяемым результатом. После неё просмотри
`git diff` и запусти подходящие unittest из .venv. Для передачи работы между
помощниками используй HANDOFF.template.md: запиши цель, изменённые файлы,
результаты проверок и следующий шаг. История диалога сама между ними не переносится.

Критерий готовности: проходят smoke/tools, Harness читает правильный workspace,
выполняет небольшую правку и проверку, а результат можно проверить по diff.
Пока эти действия не выполнены, подключение считается подготовленным, не проверенным.

Для других проектов можно скопировать local-agent/ и написать их собственный
AGENTS.md. Эти настройки не меняют модель оценки вакансий в HH Assistant.
